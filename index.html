รับหิ้วระหว่างทาง

ผู้ซื้อฝากคำขอ → คนที่ผ่านร้านและไปทางเดียวกันกดรับหิ้ว → ผู้ซื้อจ่ายเงิน → ผู้รับหิ้วซื้อของระหว่างทาง → นัดรับของ

ฐานของต้นแบบ: LINE OA + LIFF · 2 OA Push ต่อออเดอร์ปกติ
ผู้รับหิ้วเปิดตรวจคำขอเวลา 17:00 และเปิดสรุปรายการก่อนออกซื้อเวลา 17:15 จึงไม่ต้อง Push ทุกออเดอร์เข้าใหม่ ผู้ซื้อได้รับแจ้งเมื่อมีคนรับคำขอและเมื่อของถึงจุดนัด ตัวเลข เวลา ร้าน และค่าธรรมเนียมทั้งหมดเป็นตัวอย่างสมมติ

สมมติฐานเรื่องเงินตามแนวคิดผู้ใช้: ผู้ซื้อจ่าย 105 บาท = สินค้า 90 + ค่าหิ้ว 15 ระบบจ่ายค่าสินค้า 90 ให้ผู้รับหิ้วก่อนซื้อ หลังส่งมอบจ่ายค่าหิ้วสุทธิ 13 และหักค่าระบบสมมติ 2 บาท การรับเงิน โอนออก และคืนเงินจริงยังต้องเลือกช่องทางและยืนยันเงื่อนไขก่อนเปิดใช้จริง เงิน 90 ที่จ่ายออกก่อนส่งมอบยังมีความเสี่ยงสูญหาย

วิธีอ่าน: ไล่เลข 01–12 และตามลูกศร ป้ายบนการ์ดบอกว่าใครเห็นหน้านี้และอยู่ในแชท OA หรือหน้า LIFF (หน้าเว็บที่เปิดใน LINE) ส่วนคอลัมน์กลางอธิบายสิ่งที่ระบบทำ ปุ่มสีเข้มในไฟล์นี้ใช้ข้ามไปดูภาพขั้นถัดไปเท่านั้น

01 เปิดรอบ / ฝากซื้อ02 รับคำขอ / จ่าย03 ซื้อ / รับของ04 กรณีติดขัดสรุปการแจ้งเตือน

01 · บอกว่าจะไปไหน และฝากซื้ออะไร

สองฝั่งใช้ OA บัญชีเดียวกัน เมนูเลือกตามสิ่งที่จะทำ คนเดียวสลับเป็นผู้ซื้อหรือผู้รับหิ้วได้

02 · ผู้รับหิ้วรับคำขอ แล้วผู้ซื้อจ่ายเงิน

แจ้งผู้ซื้อเมื่อมีคนรับคำขอหนึ่งครั้ง ผู้รับหิ้วเปิดรายการตามเวลาที่ตกลง ไม่ Push คำขอใหม่ทุกครั้ง

03 · ผู้รับหิ้วซื้อของ แล้วนำมาส่งที่จุดนัด

ผู้รับหิ้วดูรายการชำระแล้วก่อนออกซื้อ ผู้ซื้อได้รับ Push ครั้งที่สองเมื่อของถึงจุดรับ

04 · ถ้าไม่มีคนรับ จ่ายไม่ทัน หรือซื้อไม่ได้

สอง Push เป็นเส้นทางปกติ เหตุที่กระทบเงินหรือเวลารับอาจต้องใช้ Push เพิ่มตามจำนวนผู้ได้รับผลกระทบ

สรุปการแจ้งเตือนที่ใช้จริงใน flow นี้

เหตุการณ์ใครได้รับ / ช่องทางโควต้า OA
ค้นหา ถามข้อมูล เปิดเมนูดูคำขอตอบคนที่ส่งข้อความหรือกดปุ่ม ด้วย Reply API ที่ยังมีสิทธิ์ตอบ0
เปิดรอบ ฝากคำขอ ดูสถานะชำระเงิน ดูรายการซื้อและรายได้แสดงใน LIFF ที่ผู้ใช้เปิดอยู่ ไม่ส่งข้อความซ้ำ0
มีผู้รับหิ้วยืนยันPush #1 ให้ผู้ซื้อ → ปุ่มเปิดหน้า LIFF ชำระ1 ต่อออเดอร์
ถึงจุดนัด พร้อมรับPush #2 ให้ผู้ซื้อ → ปุ่มเปิดรหัสรับของ1 ต่อออเดอร์
เตือนผู้รับหิ้วก่อนตรวจ/ก่อนออกซื้อตัวเลือกเสริม: เตือนหนึ่งครั้งต่อรอบ หากผู้รับหิ้วต้องการเพิ่ม 1 ต่อการส่งถึงผู้รับหิ้วหนึ่งคน
ล่าช้า ซื้อไม่ได้ ยกเลิก เงินมีปัญหาPush เฉพาะผู้ได้รับผลกระทบ พร้อมเหตุและทางดำเนินการเพิ่มตามจำนวนผู้รับและจำนวนครั้งที่ส่ง

100 ออเดอร์ปกติ ≈ 200 OA Push หากเพิ่มเตือนผู้รับหิ้ว 10 รอบ จะเป็นประมาณ 210 หน่วย ก่อนรวมเหตุผิดปกติและข้อความอื่น การนับนี้สมมติว่าคำขอใหม่ไม่ถูก Push ไปหาผู้รับหิ้วทุกครั้ง

กดใน LIFF ไม่ได้สร้างสิทธิ์ Reply ให้แจ้งอีกคนฟรี ข้อมูลการชำระและผลโอนต้องมาจากระบบรับเงินจริง หน้าเหล่านี้เป็นภาพแนวคิด ไม่มีการรับหรือโอนเงินจริง

ถ้าจะใช้ LINE MINI App แทนหน้า LIFF

หน้าฟอร์มและหน้ารายการใช้แนวทางเดียวกันได้ ส่วนข้อความธุรกรรมบางกรณีอาจเปลี่ยนจาก OA Push เป็น Service messages ของ MINI App ที่ผ่านการรับรองและเทมเพลตผ่านอนุมัติ ข้อความออกในห้อง LINE MINI App Notice ไม่ใช่ห้อง OA นี้ จึงไม่นับลด Push ในแผนต้นแบบจนกว่าจะยืนยันสิทธิ์และกรณีใช้งานจริง
